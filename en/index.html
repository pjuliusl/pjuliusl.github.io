Projects

ai / mlops

Fine-tuning and evaluating decision models

I built the LoRA fine-tuning pipeline for a model that sorts records into four categories. I group the splits by record, so the same case can't show up in both training and test. Training runs as a GPU Job on Kubernetes with checkpoints and resume, and MLflow stores parameters and metrics. I pick the checkpoint by its severe-error limit, and at export I compare training outputs with serving outputs before I release the version.

PyTorch · Transformers · PEFT · MLflow · K3s

  1. Split by record
  2. LoRA fine-tuning
  3. Independent evaluation
  4. Blind human review
  5. Training × serving parity

ai / human evaluation

Human review platform for AI answers

  1. queue
  2. blind review
  3. rationale
  4. metrics

Analysts review answers without knowing whether a model or another analyst wrote them. The platform has a work queue, a written reason for each decision and a history of every review. Dashboards show agreement, severe errors, coverage and confidence. Login uses Argon2id and locks after repeated failed attempts.

ai / conversation

Assistant for filing police reports

  1. report
  2. rules engine
  3. LLM
  4. narrative

A rules engine checks what the report still lacks and whether the case can be filed online. An LLM picks the next question and drafts the narrative, and the engine rejects facts the citizen didn't state. If the report points to immediate danger, the assistant tells the person to call 190, the police emergency line. On every commit, simulated citizens talk to the assistant and an evaluator compares the result with an answer key.

FastAPI · LLM · LiteLLM · pytest

ai / fork of an open source project

Chat Infinito, a fork of UniiChat

  1. chat
  2. summaries
  3. tree
  4. exact search

UniiChat, by Victor Taelin, is a chat that never ends: it keeps the whole conversation in a tree of summaries and reopens old parts when it needs them. In my fork I replaced API keys with Claude and ChatGPT subscriptions, calling the official claude and codex clients. Codex writes the summaries in batches, and when one plan hits its limit another model takes over. I added exact search over the history, a rule that keeps links and numbers in the summaries and live subscription usage on screen.

TypeScript · Bun · Claude Code · Codex CLI · MCP
